# macOS AppIcon asset catalog for StandUp

Adds a macOS application icon to the StandUp menu bar app by introducing an `Assets.xcassets` catalog with a full `AppIcon.appiconset` (ten PNGs, 16–1024px) generated by downscaling the 1254×1254 source image, and wiring it to the app target through a single `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` build setting on both Debug and Release. The project is an Xcode 16+ synchronized-folder project (`objectVersion = 77`), so catalog membership comes automatically from the `PBXFileSystemSynchronizedRootGroup`; no file reference or Resources-phase entry is added. The menu bar icon (an SF Symbol) is untouched, matching the user's requirement that only the application/Spotlight icon change. Build evidence recorded by the implementer shows `AppIcon.icns`, `Assets.car`, and `CFBundleIconName/CFBundleIconFile = AppIcon` in the built bundle.

Watch for: the implementation deliberately omits the PBXFileReference/Resources-phase edits the task brief prescribed, because this is a synchronized-folder project where those edits would double-register the catalog (confirmed, non-blocking — the chosen wiring is the correct one for `objectVersion 77`). README.md and the source `docs/images/screenshot.png` are bundled into the same commit (confirmed, non-blocking).

**Verdict**: APPROVED

## High-level view

The catalog is structurally sound. The appiconset carries all ten standard macOS entries (16/32/128/256/512 at @1x and @2x), every `filename` in `Contents.json` has a matching PNG on disk, and the pixel dimensions are exactly right (16, 32, 32, 64, 128, 256, 256, 512, 512, 1024). The master is 1024px and the source is 1254px, so every file is a downscale — nothing was upscaled.

The project wiring diverges from the literal task brief but is correct for the project format. Rather than adding a `PBXFileReference`, a `PBXBuildFile`, and a Resources-build-phase entry with fresh object IDs, the change adds only `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` to the two app-target build configs. In a synchronized-folder project (`objectVersion = 77`), anything dropped under the synchronized `StandUp/` folder is already a target member; adding explicit references would register the catalog twice and trigger a duplicate-output build error. The two edited configs (`A1000018` Debug, `A1000019` Release) are confirmed members of the `StandUp` app target's config list, not the test target.

`MenuBarLabelView.swift`, `MenuBarContentView.swift`, and `StandUpApp.swift` are absent from the commit, so the SF Symbol menu bar label is unchanged, as the user required.

### Asset catalog structure

The top-level `Assets.xcassets/Contents.json` carries only the `author: xcode / version: 1` metadata that marks the folder as a catalog for `actool`. The `AppIcon.appiconset/Contents.json` lists exactly ten `mac`-idiom images spanning 16x16, 32x32, 128x128, 256x256, and 512x512 at both 1x and 2x. Each `filename` entry resolves to a PNG that exists on disk, and the on-disk pixel dimensions line up with the point-size × scale product for every entry:

```
icon_16        16     icon_16@2x     32
icon_32        32     icon_32@2x     64
icon_128      128     icon_128@2x   256
icon_256      256     icon_256@2x   512
icon_512      512     icon_512@2x  1024
```

The 32px and 256px pixel dimensions each appear twice (as the @2x of one size and @1x of the next); the duplicated files are byte-identical in size (icon_16@2x/icon_32 both 2680 bytes, icon_128@2x/icon_256 both 70798, icon_256@2x/icon_512 both 259883), consistent with reusing one render per unique dimension. The master is 1024px (icon_512@2x) and the source is 1254px, so every file is a downscale.

### Synchronized-folder wiring instead of explicit references

The project is `objectVersion = 77` with `StandUp` declared as a `PBXFileSystemSynchronizedRootGroup` (`A1000020`) attached to the app target. The only `.pbxproj` change is one added line per build config:

```
+				ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon;
```

on `A1000018` (Debug) and `A1000019` (Release), both of which belong to `A1000012 /* Build configuration list for PBXNativeTarget "StandUp" */` — the app target, with `PRODUCT_BUNDLE_IDENTIFIER = com.standup.app` and `INFOPLIST_FILE = StandUp/Info.plist`. The test target's configs (`A100001A`/`A100001B`, bundle id `com.standup.app.tests`) and the project-level configs (`A1000016`/`A1000017`) are left alone. `grep -c` for the new setting returns 2.

The task brief called for a PBXFileReference, a PBXBuildFile, and a Resources-build-phase entry with new 24-char object IDs. Those were deliberately not added. The sync group's exception set (`A1000022`) only excludes `Info.plist` and `StandUp.entitlements`, so `Assets.xcassets` under `StandUp/StandUp/` is an automatic target member; adding explicit references on top of that would make the catalog a member twice and produce a duplicate-output build failure. The build evidence (BUILD SUCCEEDED, `Assets.car` + `AppIcon.icns` in `Contents/Resources/`, `CFBundleIconName`/`CFBundleIconFile = AppIcon` in the bundle Info.plist) confirms the icon compiles and embeds with the chosen wiring, so the deviation is correct for this project format.

### Menu bar left untouched

`git show --name-only` on the commit lists no `MenuBar*` or `StandUpApp.swift` paths, and a diff restricted to those three files is empty. The SF Symbol menu bar label is therefore unchanged, satisfying the user's constraint that only the application/Spotlight icon should get the logo while the menu bar stays as-is.
